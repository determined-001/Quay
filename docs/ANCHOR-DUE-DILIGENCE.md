# Anchor due diligence

This describes the implemented `OFFRAMP=anchor` / `testanchor` seller-initiated flow. The production adapter uses SEP-10, SEP-12, SEP-38 and SEP-6; the SEP-24 adapter exists in source but is not wired into the API. An anchor must confirm its own licensing, supported corridor, KYC fields, payout rail, data retention, and incident contact before launch. [API wiring](../apps/api/src/services/container.ts#L388-L444) · [Mainnet checklist](MAINNET.md#L90-L119) · [SEP-24 limitation](ARCHITECTURE.md#L331-L337)

## Custody and authority

```text
Buyer wallet ── Stellar payment ──> Seller wallet
                                  │
                                  └── seller-signed withdrawal transfer ──> Anchor wallet ──> payout rail
Quay API (production, DEFAULT_SELLER_SECRET unset): link tracking, KYC relay, quotes, withdrawal initiation, status
```

`POST /links` sets the payment destination to the authenticated seller's wallet, and the browser asks the seller's wallet to sign any later withdrawal transfer. Quay's current service composition gives the anchor adapter a seller-scoped JWT, not a seller keypair; the server cannot sign a payment or a seller's SEP-10 challenge with its production signing key. The planned inline mode is not implemented. [Link destination](../apps/api/src/services/link-service.ts#L329-L365) · [Wallet transfer signing](../apps/web/lib/wallet.ts#L137-L184) · [Anchor wiring](../apps/api/src/services/container.ts#L389-L444) · [Modes](../packages/core/src/ports/index.ts#L85-L111)

The seller's anchor JWT is a **bearer credential**, even though it cannot sign a Stellar payment. It can read or update that seller's KYC and initiate a withdrawal request; treat theft of it as a privacy and payout incident. The anchor pays only after the seller separately signs and sends the requested asset. ## Data flow and retention

Production integration must use HTTPS end to end. The public-network configuration rejects a non-HTTPS `ANCHOR_URL`, and SEP-1 discovery itself uses HTTPS, but the client follows endpoint URLs advertised in the anchor's TOML; verify **each** advertised SEP endpoint is HTTPS before launch. SEP-6 withdrawal initiation uses a GET whose query string includes `dest` and `dest_extra` payout values, so the anchor must keep URL/access logs appropriately protected. Stellar payments and seller withdrawal transfers are submitted to the public ledger. The table describes Quay's local persistence. **The application has no general TTL or deletion job for seller, KYC, payout, link, off-ramp, or webhook-history rows.** Expiry on a link, quote, JWT, or webhook secret changes validity/state; it is not a data-deletion promise. Anchor-side retention, backup retention, and legal retention must be agreed with the operator and anchor separately. ## Seller identity and wallet changes

Each seller is their **own anchor customer**: the expected JWT `sub` is the seller's wallet. Quay rejects a *present but mismatched* `sub`; the current code does not require the claim to be present, so the anchor's JWT format must be verified before integration. Quay only reuses an anchor session when its stored account matches the current seller account. A changed wallet needs a new wallet-signed anchor challenge; signing in with another wallet ordinarily creates a distinct seller record. The KYC adapter does not reuse an anchor `customer_id` from another account. ## Contacts and incidents

Before integration, exchange named security and operations contacts with the anchor, agree an incident notification channel and response window, and document who can suspend withdrawals, revoke anchor JWTs, rotate encryption keys and notify affected sellers. Quay's operational response steps are in the [runbook](RUNBOOK.md#L391-L416) and its [incident template](RUNBOOK.md#L471-L494); report vulnerabilities privately through [SECURITY.md](../SECURITY.md#L7-L26). These are integration actions for the operator, not promises that an anchor contract or notification SLA already exists. [Mainnet agreement requirement](MAINNET.md#L101-L119)
